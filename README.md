# 气象预警信息平台（方案与最小可用原型）

这个仓库提供一个可落地的 MVP 设计：
- 接入国家预警信息发布平台数据；
- 读取腾讯在线文档中的项目清单；
- 按项目所在区域匹配预警信息；
- 通过钉钉机器人通知相关人员。

## 1. 整体架构

```text
国家预警平台 API/数据源
          |
          v
  [预警采集模块 fetch_alerts]
          |
          v
  [标准化模块 normalize_alerts]
          |
          +---------------------+
                                |
腾讯在线文档 API/导出           v
          |              [匹配引擎 match_projects]
          v                     |
 [项目清单采集 fetch_projects]   v
                     [告警去重/抑制 dedup]
                                |
                                v
                     [通知模块 notify_dingtalk]
                                |
                                v
                            相关人员
```

## 2. 数据模型建议

### 2.1 项目表（来自腾讯在线文档）
建议至少包含：
- `project_id`：项目唯一 ID
- `project_name`：项目名
- `province` / `city` / `district`：省市区
- `geo_code`：行政区划代码（建议优先维护）
- `owner`：负责人
- `notify_group`：钉钉群标识或机器人映射
- `severity_threshold`：通知级别阈值（如黄色及以上）

### 2.2 预警表（来自国家预警平台）
建议标准化字段：
- `alert_id`：预警唯一 ID
- `title`：预警标题
- `alert_type`：预警类型（暴雨/雷电/高温等）
- `level`：蓝/黄/橙/红
- `region_name`：区域名称
- `geo_code`：区域代码
- `start_time` / `end_time`
- `status`：生效、解除等

## 3. 匹配策略

优先级建议如下：
1. **geo_code 精确匹配**（最可靠）；
2. 若缺失 geo_code，则做 `省/市/区` 分层匹配；
3. 对同一项目同一告警类型做去重：
   - 当 `alert_id` 相同，不重复通知；
   - 当 `alert_id` 变更且级别升高，立即通知；
   - 当告警解除，发送恢复通知（可选）。

## 4. 通知策略（钉钉）

消息建议包含：
- 项目名称、区域
- 预警类型、级别、生效时间
- 处理建议（如“暂停室外施工”）
- 数据来源与更新时间

可增加：
- 按项目自定义通知阈值（例如仅橙色/红色触发）；
- 夜间静默与值班白名单；
- 同类告警合并推送。

## 5. 运行方式（MVP）

- 定时执行（每 5~10 分钟）或事件驱动；
- 将最近一次发送记录存储在本地 SQLite/Redis；
- 首先用 1~2 个城市试点，验证误报/漏报后再全量上线。
